Abstract

This report implements the method described in A Statistical Approach to Texture Classification from Single Images. The method classifies textures in an image by comparing them with a prepared library of texture representatives. The project prepares a representative texture library and implements the filters proposed in the paper in a segmentation program. The goal is to verify the classification efficiency reported by the paper.

1. Introduction

Recognizing textures in an image is difficult. Many textures look similar, and their orientation makes identification even harder. The authors of the selected paper therefore propose a filter bank and a method that partly compensates for texture rotation.

Filters are applied to a training set of images containing one texture. The filter responses are clustered with k-means; the resulting representatives are called textons and are stored in a texton library. A new image is convolved with the filters and every response is described by the closest texton. A histogram of texton occurrences then becomes the model of the image.

The texton library has to be prepared before the segmenter runs. If the expected textures and a database of samples are known, the library can be built in advance. This preparation, as well as the preparation of the filter bank, is expected to be computationally expensive, so both are supplied to the program as precomputed data. The filter bank should be independent of the texture library and designed as a general-purpose component.

The paper compares Leung–Malik, Schmid, and Maximum Response filter banks. The implementation prepares all three so that their results can be compared for different textures. The filters are represented as grayscale images with a fixed size of 64 x 64 pixels.

The project also implements a method for generating the texton library. It loads the prepared filters, runs k-means over their responses, and saves an importable library file. The library should cover the complete set of textures used by the segmenter. It requires several samples from each category, captured with different orientations and lighting conditions.

The segmenter extracts texton information and builds a histogram of texton frequencies. Most of the work therefore takes place in the Features component. The Clustering and Postprocessing components are changed less; the aim is to experiment with the extracted texture information and to see how it can be used by the segmenter.

2. Segmenter

The method from the paper does not fit the original segmenter perfectly. It classifies the texture inside a segment rather than creating the segments itself. The implementation therefore tests whether the texton description can be assigned to every pixel, so that segments can subsequently be built from the pixel-level information.

The processing of one texton is as follows:

  1. Convolve the texton with every filter.
  2. Describe each convolution response by the closest texton in the library.
  3. Build a histogram of texton occurrences as the texture description.

This is the basic algorithm described in the paper. The process is the same for training and test images; the difference is which data are used to build or evaluate the model.

2.1. Features

The segmenter needs at least the following parameters:

  • a path to the filter-library directory;
  • a path to the texton-library directory;
  • the input-image scale;
  • the size of the sliding window;
  • the filter size;
  • the number of filters;
  • the number of textures in the library;
  • a file filter for the library data.

2.2. Transformation

The texton information is obtained in three steps:

  1. Convolve the texton with all filters.
  2. Replace every convolution response with the nearest texton in the library.
  3. Use the resulting texton histogram as the description of the texture.

After implementing this basic algorithm, the suitability of the filter banks and the accuracy of the library can be compared.

2.3. Segmentation

For segmentation it is more useful to keep several nearest textons instead of only one. The paper also selects several good matches. In a region containing one coherent texture, the description should therefore be clear; at a boundary between textures, it should be less certain.

Because the goal is not only to describe one image and identify its texture, the final step of building one image histogram is omitted. Instead, every pixel is treated as the centre of a texton. The neighbouring pixels are searched with a sliding window. If matching classifications are found, the neighbourhood is marked as a coherent segment.

The output consists of the three best texture matches. They are ranked by the extent of the filter response, and several matches may correspond to the same texture.

3. Results

With a small number of filters and a small window, many regions are classified incorrectly. The method does not treat textures as colours but as patterns, so similar patterns can be found in different textures.

The experiments use images scaled to one quarter of their original size. The middle configuration evaluates the data relatively accurately, but some regions are assigned to the wrong texture. In that case, the downscaling and the insufficient sample for the comparison histogram are the likely causes.

With a large sliding window, the boundaries are strongly distorted because the window covers a large part of the image. The window should therefore be substantially smaller than the image being classified.

The CS scores range from 0 to 10, depending on the parameters. Eight filters are too few; from about fourteen filters the results become reasonable. Even small windows provide partly usable results.

4. Summary

The basic algorithm is not well suited to the original segmentation problem, but its modification can achieve partial success. For computational reasons, it is preferable to prepare the texton library in a separate program and use the precomputed library in the segmenter.

The filters can be stored as images or generated in Matlab from the available code. The texture library is downloaded from the Mosaic server. The method works on small data, and larger experiments were used to measure the effect of the number of filters and the sliding-window size.

The full filter bank with chi-squared histogram comparison takes hours for one task on the available hardware, so the optimal window size was not found. A grid search on a computing cluster would be a natural next step. It is likely that the best window size lies between zero and twice the filter size, and that reducing the number of filters could improve speed at the cost of small inaccuracies. A smaller window improves boundary localization but also leaves fewer samples for the histogram comparison. The method is therefore not especially suitable for detecting boundaries, although it can classify individual textures reasonably well when enough surrounding area is available.
